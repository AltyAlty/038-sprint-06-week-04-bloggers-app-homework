В PostgreSQL можно использовать:
1. Операторы сравнения:
1.1 Равенство: "=".
1.2 Неравенство: "<>" или "!=".
1.3 Меньше: "<".
1.4 Меньше или равно: "<=".
1.5 Больше: ">".
1.6 Больше или равно: ">=".
2. Арифметические операторы:
2.1 Сложение: "+".
2.2 Вычитание: "-".
2.3 Умножение: "*".
2.4 Деление: "/".
2.5 Деление по модулю: "%".

/*--------------------------------------------------------------------------------------------------------------------*/

Использование конкатенации в чистых запросах в приложении может быть опасно, так как при конкатенации пользовательский
ввод встраивается прямо в текст запроса, что открывает возможность для SQL-инъекций. Безопаснее использовать
параметризованные запросы, так как они передают ввод отдельно от кода, поэтому СУБД воспринимает его только как данные.
Использование конкатенация может быть допустимо только для неизменяемых технических элементов, например, при подстановке
проверенного имени колонки из разрешенного списка полей для сортировки, так как имена полей нельзя параметризовать.

/*--------------------------------------------------------------------------------------------------------------------*/

Типы ключевых слов в PostgreSQL:
1. Команда - это законченная инструкция для сервера БД.
2. Клауза/Предложение - это часть команды, уточняющая ее поведение.
3. Оператор - это символ или слово, выполняющее действие над значениями.
4. Ограничение - это правило для поля или таблицы.
5. Тип данных - это характеристика поля, определяющая допустимый формат и множество значений, которые в нем можно
хранить.
6. Функция - это именованная операция, возвращающая результат.
7. Литерал - это слово, обозначающее конкретное значение.

В PostgreSQL при написании запросов ключевые слова не чувствительны к регистру, но их принято писать в верхнем регистре.

Элементы синтаксиса в PostgreSQL:

1. Команда "CREATE" - это команда, позволяющая создавать новые объекты в БД:
1.1 После команды "CREATE" требуется указывать части команда, поясняющие какой именно объект необходимо создать:
- CREATE DATABASE - БД.
- CREATE TABLE - таблица.
- CREATE INDEX - индекс.
- CREATE SCHEMA - схема.
- CREATE VIEW - представление.
- CREATE MATERIALIZED VIEW - материализованное представление.
- CREATE SEQUENCE - последовательность.
- CREATE FUNCTION - функция.
- CREATE PROCEDURE - процедура.
- CREATE TRIGGER - триггер.
- CREATE TYPE - пользовательский тип данных.
- CREATE DOMAIN - домен (тип с ограничениями).
- CREATE ROLE - роль или пользователь.
- CREATE EXTENSION - расширение.
- CREATE TABLESPACE - табличное пространство.
- CREATE AGGREGATE - агрегатная функция.
- CREATE OPERATOR - оператор.
- CREATE RULE - правило.
- CREATE POLICY - политика безопасности.
- CREATE PUBLICATION - публикация (репликация).
- CREATE SUBSCRIPTION - подписка (репликация).
- CREATE COLLATION - правило сортировки.
- CREATE CONVERSION - преобразование кодировок.
- CREATE FOREIGN DATA WRAPPER - обертка внешних данных.
- CREATE SERVER - внешний сервер.
- CREATE FOREIGN TABLE - внешняя таблица.
- CREATE USER MAPPING - маппинг пользователя.
- CREATE STATISTICS - расширенная статистика.
- CREATE TRANSFORM - преобразование типа.
- CREATE LANGUAGE - процедурный язык.
- CREATE CAST - приведение типов.
- CREATE EVENT TRIGGER - событийный триггер.
- CREATE ACCESS METHOD - метод доступа.
- CREATE GROUP - группа (устаревший синоним CREATE ROLE).
- CREATE TEXT SEARCH CONFIGURATION - конфигурация полнотекстового поиска.
- CREATE TEXT SEARCH DICTIONARY - словарь полнотекстового поиска.
- CREATE TEXT SEARCH PARSER - парсер полнотекстового поиска.
- CREATE TEXT SEARCH TEMPLATE - шаблон полнотекстового поиска.
1.2 После части команды, поясняющей какой именно объект необходимо создать, требуется указывать имя для создаваемого
объекта.
1.3 Для указания дополнительных параметров требуется использование клаузы "WITH". Какие именно дополнительные параметры
можно указывать зависит от типа создаваемого объекта. Значение дополнительного параметра указывается при помощи знака
"=". Например, дополнительные параметры при создании БД для команды "CREATE DATABASE":
- OWNER - имя пользователя, который будет владельцем БД.
- TEMPLATE - имя базы-шаблона, с которой скопируется структура, по умолчанию "template1".
- ENCODING - кодировка базы.
- LOCALE - общие региональные настройки.
- LC_COLLATE - правило сортировки строк.
- LC_CTYPE - классификация символов, например, что считается буквой, регистры.
- LOCALE_PROVIDER - поставщик локалей, например "libc" или "icu".
- ICU_LOCALE - локаль для провайдера ICU, например, "en-US".
- ICU_RULES - кастомные правила сортировки для ICU.
- COLLATION_VERSION - версия правил сортировки.
- TABLESPACE - имя табличного пространства, где необходимо хранить файлы БД, по умолчанию, "pg_default".
- CONNECTION LIMIT - максимальное количество одновременных подключений, если указано -1, то без ограничений.
- ALLOW_CONNECTIONS - разрешать ли подключаться к БД.
- IS_TEMPLATE - сделать ли эту БД шаблоном для создания других БД.
- STRATEGY - способ копирования шаблона, например, "WAL_LOG" или "FILE_COPY".
1.4 При создании таблицы для команды "CREATE TABLE" очень редко используется клауза "WITH", но всегда указываются
настройки полей таблицы в круглых скобках. В этих настройках для того, чтобы пометить какое-то поле как PK, нужно
использовать ограничение "PRIMARY KEY" после указания типа поля или указать имя поля так: "PRIMARY KEY (field_name)".
При описании поля таблицы можно использовать ограничение "NOT NULL", чтобы указать, что это поле не может быть литералом
"NULL". Также при описании поля таблицы можно использовать ограничение "DEFAULT" для задания значения по умолчанию. Если
нужно пометить какое-то поле как FK, то можно использовать ограничение "FOREIGN KEY (field_name)", при этом после этого
можно использовать:
- Часть ограничения "REFERENCES" для указания на какую таблицу и поле ссылается этот FK.
- Часть ограничения "MATCH SIMPLE" для указания режима проверки составных FK, где часть ограничения "SIMPLE" допускает
литерал "NULL" в части полей (указано по умолчанию).
- Опция ограничения "ON UPDATE NO ACTION" для указания запрещать изменять поле, на которое ссылается FK (указано по
умолчанию).
- Опция ограничения "ON DELETE NO ACTION" для указания запрещать удалять запись, на которую ссылается FK (указано по
умолчанию).
Также какое-то поле можно пометить как FK путем указания части ограничения "REFERENCES" после типа поля.
1.5 Примеры:

1.5.1 Создание БД:

CREATE DATABASE "Examples_001"
	WITH
		OWNER = postgres
		ENCODING = 'UTF8'
		LOCALE_PROVIDER = 'libc'
		CONNECTION LIMIT = -1
		IS_TEMPLATE = false;

1.5.2 Создание таблицы c PK:

CREATE TABLE users (
	id SERIAL PRIMARY KEY,
	first_name VARCHAR,
	last_name VARCHAR,
	passport_number VARCHAR,
	is_married BOOLEAN
);

или

CREATE TABLE public.users (
	id serial,
	first_name character varying,
	last_name character varying,
	passport_number character varying,
	is_married boolean,
	PRIMARY KEY (id)
);

1.5.3 Создание таблицы с PK и FK:

CREATE TABLE public.wallets (
	id UUID NOT NULL DEFAULT gen_random_uuid() PRIMARY KEY,
	title VARCHAR,
	currency CHAR(3),
	owner_id INT,
	FOREIGN KEY (owner_id)
		REFERENCES public.users (id) MATCH SIMPLE
		ON UPDATE NO ACTION
		ON DELETE NO ACTION
);

1.5.4 Создание таблицы с PK и двумя FK:

CREATE TABLE public.wallets_sharing (
	id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
	wallet_id UUID,
	user_id INT,
	added_date DATE DEFAULT CURRENT_DATE,
	status SMALLINT,
	FOREIGN KEY (wallet_id)
		REFERENCES public.wallets (id) MATCH SIMPLE
		ON UPDATE NO ACTION
		ON DELETE NO ACTION,
	FOREIGN KEY (user_id)
		REFERENCES public.users (id) MATCH SIMPLE
		ON UPDATE NO ACTION
		ON DELETE NO ACTION
);

1.5.5 Создание таблицы, где одно и то же поле является и PK, и FK:

CREATE TABLE public.profiles (
    hobby VARCHAR,
    education VARCHAR,
    user_id INT NOT NULL PRIMARY KEY,
    FOREIGN KEY (user_id)
        REFERENCES public.users (id)
		MATCH SIMPLE
        ON UPDATE NO ACTION
        ON DELETE NO ACTION
);

2. Команда "INSERT" - это команда, позволяющая добавлять новые записи в таблицу:
2.1 Может использоваться с необязательным клаузой "INTO".
2.2 После команды "INSERT" или клаузы "INTO" требуется указание имени таблицы с перечислением в круглых скобках имен
полей этой таблицы.
2.3 После перечисления полей таблицы требуется использовать клаузу "VALUES" с перечислением в круглых скобках значений
полей в записи в том же порядке, в котором они были указаны после команды "INSERT" или клаузы "INTO".
2.4 Через запятую можно указывать круглые скобки несколько раз, если нужно добавить больше одной записи в таблицу.
2.5 В конце можно использовать клаузу "RETURNING *", чтобы получить все добавленные записи со значениями всех
полей, или же вместо "*" указать имена конкретных полей.

INSERT INTO public.users (first_name, last_name, passport_number, is_married)

3. Часть клаузы "AS" - это часть клаузы, позволяющая создавать псевдонимы для имен таблиц, полей и так далее:
3.1 Указывается сразу после имени, для которого создается псевдоним, через пробел.
3.2 Во всех случаях, кроме команды создания таблицы, часть клаузы "AS" может быть опущена для создания псевдонима.
3.3 Примеры:

3.3.1 Получение данных таблицы по определенным полям, используя псевдоним для таблицы:

SELECT id, u.first_name, u.last_name, u.passport_number, u.is_married
	FROM public.users u;

или

SELECT id, u.first_name, u.last_name, u.passport_number, u.is_married
	FROM public.users AS u;

или

SELECT id, u.first_name, u.last_name, u.passport_number, u.is_married
	FROM public.users AS "u";

4. Команда "SELECT" - это команда, позволяющая получать данные таблиц:
4.1 После команды "SELECT" требуется через запятую перечислить имена полей, данные по которым нужно получить, или
указать "*", если нужно получить данные по всем полям.
4.2 После перечисления имен полей требуется использовать клаузу "FROM" для указания имени таблицы, данные из которой
нужно получить.
4.3 После клаузы "FROM" можно использовать клаузу "WHERE" для указания условий поиска данных в таблице. В работе клаузы
"WHERE" нельзя использовать агрегатные функции, например, такие, как "COUNT()", "SUM()" или "AVG()". Клауза "WHERE"
работает с каждой записью по отдельности до подсчетов и группировок. Клауза "WHERE" может работать со следующими
операторами:
- Сравнения: "=", "<>" или "!=", ">", "<", ">=", "<=".
- Проверка диапазона при помощи операторов "BETWEEN" и "AND": WHERE field_name BETWEEN num_01 AND num_02.
- Проверка по включению в список при помощи оператора "IN": WHERE field_name IN (num_01, num_02, num_03).
- Проверка по отсутствию в списке при помощи оператора "NOT IN":
WHERE field_name NOT IN (num_01, num_02, num_03).
- Поиск по шаблону при помощи операторов "LIKE" и "ILIKE". Могут использовать с частью оператора "ESCAPE" для
экранирования: WHERE email '%y!_%' ESCAPE '!'. Без части оператора "ESCAPE" для экранирования нужно использовать символ
"\": WHERE email '%y\_%'. В операторах "LIKE" и "ILIKE" символ "%" обозначает любое количество любых символов, а символ
"_" - ровно один любой символ.
- Проверка на литерал "NULL" при помощи операторов "IS NULL" и "IS NOT NULL".
- Логические связки при помощи операторов "AND", "OR" и "NOT".
4.4 В конце запроса можно использовать клаузу "ORDER BY" для сортировки получаемых данных. Эту клаузу можно
комбинировать с клаузами "LIMIT" и "OFFSET" для имитации пагинации данных.

4.5 Примеры:

4.5.1 Получение данных таблицы по определенным полям:

SELECT id, first_name, last_name, passport_number, is_married
	FROM public.users;

4.5.2 Получение данных таблицы по всем полям:

SELECT *
	FROM public.users;

4.5.3 Получение данных таблицы по всем полям по условию:

SELECT *
	FROM public.users
	WHERE id = 3;

4.5.4 Получение данных таблицы по всем полям по составному условию ('123%' означает, что поле должно начинаться со
строки "123"):

SELECT *
	FROM public.users
	WHERE
		is_married = false
		AND passport_number LIKE '123%';

4.5.5 Получение данных таблицы по всем полям по составному условию ('%456' означает, что поле должно заканчиваться на
строку "456"):

SELECT *
	FROM public.users
	WHERE
		is_married = false
		AND passport_number LIKE '%456';

4.5.6 Получение данных таблицы по всем полям по составному условию ('%234%' означает, что поле должно содержать строку
"234"):

SELECT *
	FROM public.users
	WHERE
		is_married = false
		AND passport_number LIKE '%234%';

4.5.7 Получение данных таблицы по всем полям с сортировкой по убыванию по указанному полю:

SELECT *
	FROM public.users
	ORDER BY id DESC;

4.5.8 Получение данных таблицы по всем полям с сортировкой по возрастанию по указанному полю, получая только две записи
и пропуская первую:

SELECT *
	FROM public.users
	ORDER BY id ASC
	    LIMIT 2 OFFSET 1;

4.5.9 Получение данных таблицы по всем полям с установкой дополнительного поля для всех записей, используя подзапрос:

SELECT *, (
	SELECT first_name || ' ' || last_name AS boss_name
		FROM public.users
		WHERE id = 1
	)
	FROM public.users;

5. Команда "ALTER" - это команда, позволяющая изменять объекты в БД:
5.1 После команды "ALTER" требуется указывать части команды, поясняющие какой именно объект необходимо изменить:
- ALTER TABLE - таблица.
- ALTER DATABASE - БД.
- ALTER INDEX - индекс.
- ALTER SCHEMA - схема.
- ALTER VIEW - представление.
- ALTER MATERIALIZED VIEW - материализованное представление.
- ALTER SEQUENCE - последовательность.
- ALTER FUNCTION - функция.
- ALTER PROCEDURE - процедура.
- ALTER TRIGGER - триггер.
- ALTER TYPE - пользовательский тип.
- ALTER DOMAIN - домен.
- ALTER ROLE - роль или пользователь.
- ALTER EXTENSION - расширение.
- ALTER TABLESPACE - табличное пространство.
- ALTER AGGREGATE - агрегатная функция.
- ALTER OPERATOR - оператор.
- ALTER RULE - правило.
- ALTER POLICY - политика безопасности.
- ALTER PUBLICATION - публикация.
- ALTER SUBSCRIPTION - подписка.
- ALTER COLLATION - правило сортировки.
- ALTER CONVERSION - преобразование кодировок.
- ALTER FOREIGN DATA WRAPPER - обертка внешних данных.
- ALTER SERVER - внешний сервер.
- ALTER FOREIGN TABLE - внешняя таблица.
- ALTER USER MAPPING - маппинг пользователя.
- ALTER STATISTICS - расширенная статистика.
- ALTER LANGUAGE - процедурный язык.
- ALTER EVENT TRIGGER - событийный триггер.
- ALTER DEFAULT PRIVILEGES - права по умолчанию.
- ALTER SYSTEM - глобальные настройки сервера.
- ALTER LARGE OBJECT - большой объект.
5.2 После частей команда, поясняющих какой именно объект необходимо изменить, требуется указывать имя изменяемого
объекта.
5.3 Между частями команды, поясняющими какой именно объект необходимо изменить, и именем изменяемого объекта можно
указывать часть команды "IF EXISTS", чтобы избежать ошибки, если изменяемый объект не существует.
5.4 После части команды, поясняющей какой именно объект необходимо изменить, или части команды "IF EXISTS" требуется
указывать части команды, описывающие какую именно операцию изменения необходимо провести. Например, список операций при
изменении таблицы для команды "ALTER TABLE":
- ADD COLUMN field_name type_name - добавление поля.
- DROP COLUMN field_name - удаление поля.
- ALTER COLUMN field_name TYPE type_name - изменение типа поля.
- ALTER COLUMN field_name SET NOT NULL - запретить литерал "NULL" в поле.
- ALTER COLUMN field_name DROP NOT NULL - разрешить литерал "NULL" в поле.
- ALTER COLUMN field_name SET DEFAULT value - задать значение по умолчанию для поля.
- ALTER COLUMN field_name DROP DEFAULT - удалить значение по умолчанию для поля.
- RENAME COLUMN field_name TO new_name - переименовать поле.
- RENAME TO new_name - переименовать таблицу.
- ADD CONSTRAINT constraint_name constraint - добавить именованное ограничение для поля, например, PK или FK.
- DROP CONSTRAINT constraint_name - удалить именованное ограничение для поля, например, PK или FK.
- ADD PRIMARY KEY (field_name) - добавить PK.
- ADD FOREIGN KEY (field_name) REFERENCES table_name(field_name) - добавить FK.
- ADD UNIQUE (field_name) - добавить ограничение уникальности.
- ADD CHECK check_constraint - добавить проверочное ограничение.
- OWNER TO new_user - сменить владельца таблицы.
- SET SCHEMA schema_name - переместить таблицу в другую схему.
- SET TABLESPACE tablespace_name - переместить файлы таблицы в другое место.
- ENABLE TRIGGER trigger_name - включить триггер.
- DISABLE TRIGGER trigger_name - отключить триггер.
- DISABLE TRIGGER ALL - отключить все триггеры.
- ENABLE RULE rule_name - включить правило.
- DISABLE RULE rule_name - отключить правило.
- SET (parameter = value) - изменить параметры хранения.
- RESET (parameter) - сбросить параметры хранения.
- SET LOGGED - включить ведение журнала.
- SET UNLOGGED - отключить ведение журнала.
- CLUSTER ON index_name - задать индекс для физической сортировки данных на диске.
- REPLICA IDENTITY FULL - настроить репликацию.
- ATTACH PARTITION partition_name FOR VALUES FROM value_01 TO value_02 - подключить секцию для секционированных таблиц.
- DETACH PARTITION partition_name - отключить секцию для секционированных таблиц.
- FORCE ROW LEVEL SECURITY - включить принудительную политику безопасности строк.
- NO FORCE ROW LEVEL SECURITY - отключить принудительную политику безопасности строк.
5.5 После частей команды, описывающих какую именно операцию изменения необходимо провести, в некоторых случаях можно
указывать части команды "IF EXISTS" или "IF NOT EXISTS", чтобы избежать ошибки, если изменяемый объект не существует или
существует соответственно.

5.6 Примеры:

5.6.1 Добавление поля в таблицу:

ALTER TABLE IF EXISTS public.users
	ADD COLUMN city VARCHAR;

5.6.2 Удаление поля из таблицы:

ALTER TABLE IF EXISTS public.users
	DROP COLUMN city;

5.6.3 Переименование таблицы:

ALTER TABLE IF EXISTS public.users
	RENAME TO people;

5.6.4 Переименование поля в таблице:

ALTER TABLE IF EXISTS public.users
	RENAME COLUMN passport_number TO passport;

5.6.5 Добавление уникального ограничения, чтобы нельзя было добавить больше одной записи по одним и тем же значениям
двух полей:

ALTER TABLE IF EXISTS public.wallets_sharing
	ADD UNIQUE (wallet_id, user_id);

6. Команда "UPDATE" - это команда, позволяющая изменять значения в записях:
6.1 После команды "UPDATE" требуется указывать имя таблицы, в которой необходимо изменить значения в записях.
6.2 После имени таблицы, в которой необходимо изменить значения в записях, требуется указывать клаузу "SET" и при помощи
знака "=" указывать имя поля и новое значение: "SET field_name = new_value". Если нужно поменять значения по нескольким
полям, то их можно перечислить через запятую.
6.3 Если нужно использовать данные из другой таблицы, то можно использовать клаузу "FROM" с указанием после нее имени
таблицы.
6.4 Если нужно изменить значение только в определенных записях, а не во всех, то можно использовать клаузу "WHERE" в
конце запроса с указанием после него условия поиска.
6.5 В конце можно использовать клаузу "RETURNING *", чтобы получить все измененные записи со значениями всех полей, или
же вместо "*" указать имена конкретных полей.
6.6 Примеры:

6.6.1 Изменение значения поля по условию:

UPDATE public.wallets
	SET title = 'Useless Money'
	WHERE owner_id = 4;

7. Команда "DELETE" - это команда, позволяющая удалять записи в таблице:
7.1 После команды "DELETE" требуется указывать клаузу "FROM" и имя таблицы, в которой необходимо удалить записи.
7.2 Если нужно использовать данные из другой таблицы, то можно использовать клаузу "USING" с указанием после нее имени
таблицы.
7.3 Если нужно удалить только определенные записи, а не все, то можно использовать клаузу "WHERE" в конце запроса с
указанием после него условия поиска.
7.4 В конце можно использовать клаузу "RETURNING *", чтобы получить все удаленные записи со значениями всех полей, или
же вместо "*" указать имена конкретных полей.
7.5 Примеры:

7.5.1 Удаление записей в таблице:

DELETE FROM public.wallets
	WHERE owner_id = 1;

8. Команда "TRUNCATE" - это команда, позволяющая удалять все записи в таблице, причем работая быстрее на больших
таблицах, чем команда "DELETE", так как не удаляет записи по одной, а просто очищает файлы данных целиком:
8.1 Может использоваться с необязательной частью команды "TABLE".
8.2 После команды "TRUNCATE" или части команды "TABLE" требуется указывать имя таблицы, в которой нужно удалить все
записи.
8.3 После имени таблицы, в которой нужно удалить все записи, можно указывать модификаторы "RESTART IDENTITY" или
"CONTINUE IDENTITY" для указания нужно ли сбрасывать счетчики или нет.
8.4 После модификаторов "RESTART IDENTITY" или "CONTINUE IDENTITY" можно указывать модификаторов "CASCADE" или
"RESTRICT", если нужно очистить также все таблицы, которые ссылаются на текущую таблицу через FK, или если нужно
запретить очистку таблицы, если есть ссылающиеся на нее таблицы, что является значением по умолчанию.
8.5 Примеры:

8.5.1 Удаление всех записей в таблице со сбросом счетчиков:

TRUNCATE TABLE public.users RESTART IDENTITY;

8.5.2 Удаление всех записей в таблице без сброса счетчиков:

TRUNCATE TABLE public.users CONTINUE IDENTITY;

9. Команда "DROP" - это команда, позволяющая удалять объекты в БД:
9.1 После команды "DROP" требуется указывать части команды, поясняющие какой именно объект необходимо удалить:
- DROP DATABASE - БД.
- DROP TABLE - таблица.
- DROP INDEX - индекс.
- DROP SCHEMA - схема.
- DROP VIEW - представление.
- DROP MATERIALIZED VIEW - материализованное представление.
- DROP SEQUENCE - последовательность.
- DROP FUNCTION - функция.
- DROP PROCEDURE - процедура.
- DROP TRIGGER - триггер.
- DROP TYPE - пользовательский тип данных.
- DROP DOMAIN - домен (тип с ограничениями).
- DROP ROLE - роль или пользователь.
- DROP EXTENSION - расширение.
- DROP TABLESPACE - табличное пространство.
- DROP AGGREGATE - агрегатная функция.
- DROP OPERATOR - оператор.
- DROP RULE - правило.
- DROP POLICY - политика безопасности.
- DROP PUBLICATION - публикация (репликация).
- DROP SUBSCRIPTION - подписка (репликация).
- DROP COLLATION - правило сортировки.
- DROP CONVERSION - преобразование кодировок.
- DROP FOREIGN DATA WRAPPER - обертка внешних данных.
- DROP SERVER - внешний сервер.
- DROP FOREIGN TABLE - внешняя таблица.
- DROP USER MAPPING - маппинг пользователя.
- DROP STATISTICS - расширенная статистика.
- DROP TRANSFORM - преобразование типа.
- DROP LANGUAGE - процедурный язык.
- DROP CAST - приведение типов.
- DROP EVENT TRIGGER - событийный триггер.
- DROP ACCESS METHOD - метод доступа.
- DROP ROUTINE - функция или процедура (универсальный вариант).
- DROP GROUP - группа (устаревший синоним DROP ROLE).
- DROP OWNED - все объекты, принадлежащие указанной роли.
- DROP TEXT SEARCH CONFIGURATION - конфигурация полнотекстового поиска.
- DROP TEXT SEARCH DICTIONARY - словарь полнотекстового поиска.
- DROP TEXT SEARCH PARSER - парсер полнотекстового поиска.
- DROP TEXT SEARCH TEMPLATE - шаблон полнотекстового поиска.
9.2 В случае удаления таблицы после части команды "TABLE" можно указать часть команды "IF EXISTS" и имя таблицы, чтобы
избежать ошибки, если удаляемый объект не существует.
9.3 В случае удаления таблицы после частей команды "TABLE" или "IF EXISTS" можно перечислять несколько имен таблиц через
запятую.
9.4 В случае удаления таблицы после имени удаляемой таблицы можно указывать модификаторы "CASCADE" или "RESTRICT", если
нужно удалить также все другие объекты, которые зависят от текущей таблицы, или если нужно запретить удалить таблицу,
если от нее зависят другие объекты, что является значением по умолчанию.
9.5 Примеры:

9.5.1 Удаление таблицы:

DROP TABLE public.users;

10. Клауза "JOIN" - это клауза, используемая для объединения записей из двух и более таблиц на основе условия связи
между ними:
10.1 Виды клаузы "JOIN":
- "INNER JOIN" / "JOIN" - это клауза, объединяющая данные из двух таблиц, когда в результат попадают только те записи,
для которых совпадение найдено в обеих таблицах.
- "LEFT JOIN" - это клауза, объединяющая данные из двух таблиц, когда в результат попадают все записи из левой таблицы
и только совпадающие записи из правой таблицы, причем для несовпадающих записей поля правой таблицы заполняются
литералами "NULL".
- "RIGHT JOIN" - это клауза, объединяющая данные из двух таблиц, когда в результат попадают все записи из правой
таблицы и только совпадающие записи из левой таблицы, причем для несовпадающих записей поля левой таблицы заполняются
литералами "NULL".
- "FULL OUTER JOIN" - это клауза, объединяющая данные из двух таблиц, когда в результат попадают все записи из обеих
таблиц, причем для несовпадающих записей поля противоположной таблицы заполняются литералами "NULL".
- "CROSS JOIN" - это клауза, объединяющая данные из двух таблиц, когда в результат попадают все возможные комбинации
записей, то есть каждая запись из первой таблицы соединяется с каждой записью из второй таблицы. Условие при помощи
части клаузы "ON" не используется.
- "NATURAL JOIN" - это клауза, объединяющая данные из двух таблиц, при котором PostgreSQL автоматически определяет
условие связи по полям с одинаковыми именами в обеих таблицах. Условие при помощи части клаузы "ON" не указывается.
10.2 Клаузы "JOIN" используются внутри команды "SELECT" после клаузы "FROM" и первой таблицы, но перед клаузой "WHERE".
10.3 Клаузы "JOIN" не используются напрямую в командах "UPDATE" и "DELETE", но клаузы "FROM", "USING" и "WHERE" по сути
позволяют имитировать работу клауз "JOIN".
10.4 Клаузы "INNER JOIN", "LEFT JOIN", "RIGHT JOIN" и "FULL OUTER JOIN" требуют использования части клаузы "ON" для
указания условия объединения записей в таблицах.
10.5 Можно использовать несколько клауз "JOIN" подряд для объединения более двух таблиц.
10.6 Примеры:

10.6.1 Объединение записей из двух таблиц, используя клаузу "LEFT JOIN":

SELECT w.id, w.title, w.currency, w.owner_id, u.first_name, u.last_name
	FROM public.wallets AS w
	LEFT JOIN public.users AS u
	ON w.owner_id = u.id;

10.6.2 Объединение записей из двух таблиц, используя клаузу "LEFT JOIN" и конкатенацию полей:

SELECT w.id, w.title, w.currency, w.owner_id, u.first_name || ' ' || u.last_name AS owner_full_name
	FROM public.wallets AS w
	LEFT JOIN public.users AS u
	ON w.owner_id = u.id;

или

SELECT w.id, w.title, w.currency, w.owner_id, CONCAT(u.first_name, ' ', u.last_name) AS owner_full_name
	FROM public.wallets AS w
	LEFT JOIN public.users AS u
	ON w.owner_id = u.id;

10.6.3 Объединение записей из двух таблиц, используя клаузу "LEFT JOIN" и проверку на литерал "NULL":

SELECT *
	FROM public.users
	LEFT JOIN public.profiles
	ON public.users.id = public.profiles.user_id
	WHERE public.profiles.user_id IS NULL;

или

SELECT *
	FROM public.users
	LEFT JOIN public.profiles
	ON public.users.id = public.profiles.user_id
	WHERE public.profiles.user_id IS NOT NULL;

11. Функция "COUNT" - это встроенная агрегатная функция, вычисляющая количество записей или значений и возвращающая одно
целое число типа данных "BIGINT":
11.1 Может принимать в круглых скобках символ "*", чтобы подсчитать все записи, попавшие в выборку, включая записи с
литералом "NULL" и дубликаты.
11.2 Может принимать в круглых скобках имя поля, чтобы подсчитать количество записей, где указанное поле не является
литералом "NULL".
11.3 Может принимать в круглых скобках модификатор "DISTINCT" и имя поля, чтобы подсчитать количество уникальных
значений, игнорируя дубликаты и литерал "NULL".
11.4 Используется внутри команды "SELECT":
- Как с условием при помощи клаузы "WHERE", так и без него.
- Вместе с клаузой "GROUP BY" для подсчета количества в каждой группе.
- В клаузе "HAVING" для фильтрации групп по количеству.
- В подзапросах.
11.5 Примеры:

11.5.1 Подсчет всех записей в таблице:

SELECT COUNT(*)
	FROM public.users;

11.5.2 Подсчет всех записей в таблице по условию:

SELECT COUNT(*) AS wallet_count
	FROM public.wallets
	WHERE owner_id = 1;

11.5.3 Подсчет всех записей в таблице по условию, используя подзапрос:

SELECT *, (
	SELECT COUNT(*)
		FROM public.wallets
		WHERE public.wallets.owner_id = public.users.id
	) AS wallet_count
	FROM public.users;

или

SELECT *, (
	SELECT COUNT(*) > 0
		FROM public.wallets
		WHERE public.wallets.owner_id = public.users.id
	) AS has_wallets
	FROM public.users;

или

SELECT *, (
	SELECT
		CASE WHEN COUNT(*) > 0
			THEN 'Yes'
			ELSE 'No'
		END
	FROM public.wallets
	WHERE public.wallets.owner_id = public.users.id
	) AS has_wallets
	FROM public.users;

12. Оператор "CASE" - это оператор, проверяющий условия по порядку и возвращающий значение первого условия, которое
оказалось TRUE:
12.1 Возвращает значение, поэтому может использоваться везде, где можно написать имя поля или значение:
- В команде "SELECT".
- Внутри агрегатных функций.
- В клаузе "ORDER BY".
- В команде "UPDATE".
- В клаузе "WHERE".
12.2 Используется часть оператора "WHEN" для описания условия.
12.3 Используется часть оператора "THEN" для указания возвращаемых значений.
12.4 Может использоваться часть оператора "ELSE" для указания результата, если ни одно условие не сработало.
12.5 Если часть оператора "ELSE" не указана и ни одно условие не подошло, то вернется литерал "NULL".
12.6 Требуется использование части оператора "END" в конце конструкции.
12.7 Все ветки частей оператора "THEN" и "ELSE" должны возвращать значения одного типа или совместимых типов.
12.8 Примеры:

12.8.1 Использование оператора "CASE" для проверки произвольных логических условий:

SELECT title, balance,
	CASE
		WHEN balance > 1000
			THEN 'Rich'
		WHEN balance > 0
			THEN 'Normal'
		ELSE 'Empty'
	END AS status
FROM public.wallets;

12.8.2 Использование оператора "CASE" для сравнения одного выражения со списком конкретных значений:

SELECT id, title,
	CASE status
		WHEN 1
			THEN 'Active'
		WHEN 2
			THEN 'Pending'
		WHEN 3
			THEN 'Blocked'
		ELSE 'Unknown'
	END AS status_name
FROM public.wallets_sharing
WHERE user_id = 4;

12.8.3 Использование оператора "CASE" в агрегатной функции "COUNT":

SELECT
	COUNT(
		CASE
			WHEN is_married = true
				THEN 1
			END
	) AS married_count,
	COUNT(
		CASE
			WHEN is_married = false
				THEN 1
			END
	) AS single_count
FROM public.users;

12.8.4 Использование оператора "CASE" в клаузе "ORDER BY":

SELECT *
	FROM public.wallets
	ORDER BY
		CASE currency
			WHEN 'USD'
				THEN 1
			WHEN 'EUR'
				THEN 2
			ELSE 3
		END;

12.8.5 Использование оператора "CASE" в команде "UPDATE":

UPDATE public.wallets
	SET balance = CASE
		WHEN currency = 'USD'
			THEN balance * 1.1
		ELSE balance
	END;


13. Функция "SUM" - это встроенная агрегатная функция, суммирующая числовые значения в указанном поле:
13.1 Может принимать в круглых скобках имя поля, чтобы суммировать все значения в поле, игнорируя литерал "NULL".
13.2 Может принимать в круглых скобках модификатор "DISTINCT" и имя поля, чтобы суммировать только уникальные значения
поля, игнорируя литерал "NULL".
13.3 Поле для суммирования значений обязано иметь числовой тип данных.
13.4 Если таблица пустая или в поле только литерал "NULL", то агрегатная функция "SUM" вернет литерал "NULL". Чтобы в
таком случае гарантированно получить 0 вместо литерала "NULL", нужно использовать агрегатную функцию "SUM" внутри
функции "COALESCE".
13.5 Может использоваться:
- В команде "SELECT".
- Вместе с клаузой "GROUP BY".
- В клаузе "HAVING".
- Внутри оператора "CASE".
13.6 Примеры:

13.6.1 Подсчет суммы значений в поле по условию, используя клаузу "WHERE":

SELECT SUM(balance)
	FROM public.wallets
	WHERE currency = 'USD';

13.6.2 Подсчет суммы значений в поле и их группировка:

SELECT currency, SUM(balance)
	FROM public.wallets
	GROUP BY currency;

13.6.3 Подсчет суммы значений в поле по условию и их группировка, используя клаузу "HAVING":

SELECT currency, SUM(balance)
	FROM public.wallets
	GROUP BY currency
	    HAVING SUM(balance) > 10000;

13.6.4 Подсчет суммы значений в поле по условиям, используя оператор "CASE":

SELECT
	SUM(CASE
		WHEN currency = 'USD'
			THEN balance
			ELSE 0
		END) AS usd_total,
    SUM(CASE
		WHEN currency = 'EUR'
			THEN balance
			ELSE 0
		END) AS eur_total
FROM public.wallets;

14. Клауза "GROUP BY" - это клауза, группирующая записи по указанному полю или полям, "схлопывая" записи с одинаковыми
значениями в одну:
14.1 Используется в команде "SELECT" вместе с агрегатными функциями после клаузы "WHERE" и перед клаузами "HAVING" и
"ORDER BY".
14.2 Если используется клауза "GROUP BY", то в команде "SELECT" могут быть только поля, указанные в клаузе "GROUP BY", и
агрегатные функции, например, "COUNT", "SUM", "AVG", "MIN" или "MAX".
14.3 Может группировать по нескольким полям, перечисленным через запятую.
14.4 Примеры:

14.4.1 Подсчет записей и их группировка по нескольким полям:

SELECT currency, owner_id, SUM(balance)
	FROM public.wallets
	GROUP BY currency, owner_id;

15. Клауза "HAVING" - это клауза, фильтрующая группы записей, полученные после работы клаузы "GROUP BY":
15.1 Используется только в команде "SELECT".
15.2 Может использоваться после клаузы "GROUP BY", чтобы фильтровать полученные от нее группы записей.
15.3 Может использоваться без клаузы "GROUP BY", но в таком случае PostgreSQL будет воспринимать всю таблицу как одну
большую группу.
15.4 Требует указания после себя условия для фильтрации записей. Условия могут содержать агрегатные функции или поля,
которые явно перечислены в клаузе "GROUP BY".
15.5 Примеры:

15.5.1 Подсчет записей по условию c отфильтрованной группировкой:

SELECT currency, COUNT(*)
	FROM public.wallets
	WHERE balance > 0
	GROUP BY currency
	    HAVING COUNT(*) > 1;

15.5.2 Подсчет суммы значений в поле с их фильтрацией:

SELECT SUM(balance)
	FROM public.wallets
	    HAVING SUM(balance) > 10000;

16. Клауза "ORDER BY" - это клауза, сортирующая записи в результирующем наборе данных по одному или нескольким полям,
или выражениям:
16.1 Используется только в команде "SELECT" в самом конце запроса после клауз "WHERE", "GROUP BY" и "HAVING", но перед
клаузами "LIMIT" и "OFFSET".
16.2 После нее может указываться:
- Одно или несколько имен полей через запятую.
- Порядковые номера полей.
- Выражения и оператор "CASE".
16.3 В конце клаузы "ORDER BY" может указываться тип сортировки:
- Модификатор "ASC" - сортировка по возрастанию, опция по умолчанию.
- Модификатор "DESC" - сортировка по убыванию.
16.4 В PostgreSQL при сортировке литерал "NULL" по умолчанию считается самым большим значением, но это поведение можно
явно переопределить при помощи модификаторов "NULLS FIRST" и "NULLS LAST":
- ORDER BY balance ASC NULLS FIRST - литерал "NULL" будет первым при сортировке по возрастанию.
- ORDER BY balance DESC NULLS LAST - литерал "NULL" будет последним при сортировке по убыванию.
16.5 После имени поля можно указать модификатор "COLLATE", чтобы задать правило сравнения строк. Например, следующий
вариант будет использовать сортировку строго по кодам символов ASCII, как это делает MongoDB:
ORDER BY login COLLATE "C" ASC.
16.6 Примеры:

16.6.1 Получение данных таблицы по всем полям с сортировкой по убыванию по указанному полю:

SELECT *
	FROM public.wallets
	ORDER BY balance DESC;

16.6.2 Получение данных таблицы по всем полям с сортировкой по убыванию по одному полю и с сортировкой по возрастанию по
другому полю:

SELECT *
	FROM public.users
	ORDER BY is_married DESC, last_name ASC;

16.6.3 Получение данных таблицы по всем полям с сортировкой по убыванию по указанному полю с ограничением количества
записей на вывод:

SELECT *
	FROM public.wallets
	ORDER BY balance DESC
		LIMIT 3;

16.6.4 Подсчет записей по условию c отфильтрованной группировкой и сортировкой с пагинацией:

SELECT currency, COUNT(*)
	FROM public.wallets
	WHERE balance > 0
	GROUP BY currency
		HAVING COUNT(*) > 1
	ORDER BY currency DESC
		LIMIT 5 OFFSET 0;

17. Функция "AVG" - это встроенная агрегатная функция, вычисляющая среднее числовое значение в указанном поле:
17.1 Имеет те же особенности, что и агрегатная функция "SUM".
17.2 Всегда возвращает дробное число, даже если поле имеет целочисленный тип данных.

18. Функции "MIN" и "MAX" - это встроенные агрегатные функции, находящие в указанном поле минимальное или максимальное
значение соответственно:
18.1 Имеют те же особенности, что и агрегатная функция "SUM".
18.2 Работают не только с числами, но и со строковыми и временными типами данных.

19. Функция "ROW_NUMBER()" - это встроенная оконная функция, присваивающая каждой записи порядковый номер в
результирующем наборе:
19.1 Требует указания круглых скобок, хотя ничего и не принимает.
19.2 Требует использования клаузы "OVER", внутри которого в круглых скобках должно указываться правило для нумерации,
используя клаузы "ORDER BY" и "PARTITION BY". Клауза "PARTITION BY" всегда должна идти до клаузы "ORDER BY". Клауза
"OVER" может использоваться не только в оконной функции "ROW_NUMBER()", но, например, и в агрегатной функции "SUM".
19.3 Клауза "ORDER BY" указывает в каком порядке нумеровать записи.
19.4 Клауза "PARTITION BY" указывает когда сбрасывать счетчик на 1, то есть как будто разбивать на группы.
19.5 Примеры:

19.5.1 Получение данных таблицы по всем полям и нумерация записей:

SELECT *,
    ROW_NUMBER() OVER () AS row_number
	FROM public.wallets;

19.5.2 Получение данных таблицы по всем полям и их нумерация по полю:

SELECT *,
    ROW_NUMBER() OVER (ORDER BY owner_id) AS row_number
	FROM public.wallets;

19.5.3 Получение данных таблицы по всем полям, их нумерация по полю и фильтрация:

SELECT *
	FROM (
		SELECT *,
			ROW_NUMBER() OVER (ORDER BY owner_id) AS row_number
			FROM public.wallets
	)
	WHERE row_number > 0 AND row_number < 10;

19.5.4 Получение данных таблицы по всем полям, их нумерация по полю и фильтрация, используя клаузу "WITH" (Common Table
Expression) для создания временного именованного набора данных:

WITH wallets_with_row_number AS (
	SELECT *,
		ROW_NUMBER() OVER (ORDER BY owner_id) AS row_number
		FROM public.wallets
)

SELECT *
	FROM wallets_with_row_number
	WHERE row_number > 0 AND row_number < 10;

19.5.5 Получение данных таблицы по всем полям, их нумерация по полю, сброс счетчика для каждого нового значения поля и
фильтрация:

SELECT *
	FROM (
		SELECT *,
			ROW_NUMBER() OVER (PARTITION BY owner_id ORDER BY owner_id) AS row_number
			FROM public.wallets
	)
	WHERE row_number > 0 AND row_number < 10;


19.5.6 Получение данных таблицы по всем полям и их нумерация по условию, используя оператор "CASE":

SELECT *,
	ROW_NUMBER() OVER (
		ORDER BY CASE
			WHEN currency = 'USD' THEN 1
			WHEN currency = 'RUB' THEN 2
			ELSE 3
		END
	) AS row_number
	FROM public.wallets;

19.5.7 Получение данных таблицы по всем полям, их нумерация по полю и сброс счетчика по условию, используя оператор
"CASE":

SELECT *,
	ROW_NUMBER() OVER (
		PARTITION BY CASE
			WHEN balance > 1000
				THEN 'rich'
				ELSE 'poor'
			END
		ORDER BY balance DESC
	) AS row_number
FROM public.wallets;

19.5.8 Получение данных таблицы по указанным полям с суммированием значений поля по группам, без использования оконной
функции "ROW_NUMBER()":

SELECT user_id, pay_sum, SUM (pay_sum) OVER (PARTITION BY user_id)
	FROM public.user_payments
	ORDER BY user_id;

20. Клауза "WHERE" - это клауза, фильтрующая записи по указанному условию:
20.1 Используется в командах "SELECT", "UPDATE" и "DELETE".
20.2 В условиях может использовать операторы сравнения и операторы "BETWEEN", "LIKE", "ILIKE", "IS NULL", "IS NOT NULL",
"AND", "OR" и "NOT".
20.3 Могут использоваться операторы "IN" и "NOT IN", для проверки входит ли значение в список или нет
соответственно. Если в списке есть хотя бы одно значение является литералом "NULL", то оператор "NOT IN" вернет пустой
результат, поэтому в такой ситуации лучше использовать оператор "NOT EXISTS" или оператор "NOT IN" с оператором
"IS NOT NULL" в подзапросе.

21. Оператор "::" - это оператор, приводящий значение к указанному типу данных:
21.1 Слева от оператора "::" указывается значение, а справа от него - тип данных, к которому надо привести значение,
например: '123'::integer.
21.2 Аналогично оператору "::" можно использовать оператор "CAST": CAST (field_name AS TEXT).
21.3 Для неявного приведения типов данных можно использовать оператор конкатенации "||": '' || field_name.
21.4 Существует ряд встроенных функций для явного приведения типа данных: text(field_name).

21.5 Примеры:

21.5.1 Объединение двух таблиц с сортировкой по двум полям и приведением поля к строковому типу данных, используя
оператор "::":

SELECT id, username, email
	FROM public.users
UNION
SELECT id, number_login::TEXT, email
	FROM public.admins
ORDER BY id ASC, username ASC;

21.5.2 Объединение двух таблиц с сортировкой по двум полям и приведением поля к строковому типу данных, используя
оператор "CAST":
SELECT id,
username, email
	FROM public.users
UNION
SELECT id, CAST (number_login AS TEXT), email
	FROM public.admins
ORDER BY id ASC, username ASC;

21.5.3 Объединение двух таблиц с сортировкой по двум полям и приведением поля к строковому типу данных, используя
оператор конкатенации "||" для неявного приведения:

SELECT id, username, email
	FROM public.users
UNION
SELECT id, '' || number_login, email
	FROM public.admins
ORDER BY id ASC, username ASC;

21.5.4 Объединение двух таблиц с сортировкой по двум полям и приведением поля к строковому типу данных, используя
функцию "text":

SELECT id, username, email
	FROM public.users
UNION
SELECT id, text(number_login), email
	FROM public.admins
ORDER BY id ASC, username ASC;

22. Ограничение "CHECK" - это ограничение, проверяющее, что значение в поле соответствует заданному условию:
22.1 Применяется в командах "CREATE TABLE", "ALTER TABLE" и "CREATE DOMAIN"
22.2 После ограничения "CHECK" должно указываться условие в круглых скобках.

23. Оператор "UNION" - это оператор, объединяющий результаты работы двух и более команд "SELECT" в один вертикальный
список, где записи из второго запроса добавляются под записями из первого, причем имена колонок берутся из первого
запроса:
23.1 Требуется, чтобы обе команды "SELECT" возвращали одинаковое количество полей, причем типы данных полей должны
совпадать или быть совместимыми.
23.2 Удаляет дубликаты, но можно использовать модификатор "ALL" после оператора "UNION", чтобы дубликаты не удалялись,
при этом вариант с модификатором "ALL" будет работать быстрее, так как не будет сортировки.
23.3 Примеры:

23.3.1 Объединение двух таблиц с сортировкой по двум полям:

SELECT id, username, email
	FROM public.users
UNION
SELECT id, login, email
	FROM public.admins
ORDER BY id ASC, username ASC;

24. Оператор "ANY" - это оператор, являющийся аналогом оператора "$in" из MongoDB.

25. Оператор "SOME" - это оператор, являющийся полным синонимом оператора "ANY" и аналогом оператора "$in" из MongoDB.

26. Оператор "ALL" - это оператор, требующий выполнения условия сравнения для всех элементов набора одновременно.

27. Функция "NULLIF" - это функция, сравнивающая два аргумента и возвращающая литерал "NULL", если они равны, иначе
первый аргумент.

28. Представление "VIEW" - это сохраненный SQL-запрос, к которому можно обращаться как к обычной таблице:
28.1 Данные в представлении не хранятся.
28.2 Команда "CREATE VIEW" создает представление, но выдаст ошибку, если представление с указанным именем уже существует.
28.3 Команда "CREATE OR REPLACE VIEW" создает представление или заменяет уже существующее представление с указанным
именем, но не позволяет менять количество и типы данных полей.
28.4 Если использовать часть команды "MATERIALIZED" перед частью команды "VIEW", то это позволит кэшировать данные.
28.5 Команда "ALTER VIEW" меняет метаданные представления, не трогая сам SQL-запрос.
28.6 Представления могут быть полезны для обеспечения безопасности данных, так как могут использоваться для создания
запросов, которые предоставляют только необходимые данные, избегая чувствительных.
