Индекс в MongoDB - это отдельная структура данных, в формате Self-balancing tree (B-Tree) - многопутевого
сбалансированного дерева поиска, оптимизированного для хранения отсортированных ключей и минимального числа обращений к
диску, которая хранится в MongoDB параллельно с коллекцией. Индекс не является частью документа или свойством поля.
Когда создается индекс, например, по дате создания, то MongoDB создает еще одну структуру - отсортированный список пар
примерно такого формата: Дата создания -> указатель на документ. То есть по сути дела индекс - это просто
отсортированный по какому-то критерию список ссылок на документы в коллекции. Например, если нужно отсортировать большую
коллекцию по дате создания документов, то без индексов MongoDB придется читать каждый документ в коллекции и сверять в
каждом документе поле, хранящее дату создания. Если же создан индекс по полю создания документов, то MongoDB пойдет уже
в отсортированный по дате создания список ссылок на документы коллекции и будет брать документы по порядку, без
необходимости каждый раз сверять дату создания документов, чтобы их отсортировать.

/*--------------------------------------------------------------------------------------------------------------------*/

Индексы в MongoDB ускоряют операции поиска и сортировки, но потребляют RAM и замедляют операции записи, так как при
каждой вставке, изменении или удалении документа MongoDB должна также обновлять и все связанные с ним индексы.

/*--------------------------------------------------------------------------------------------------------------------*/

Поле "_id" изначально говорит MongoDB автоматически создать уникальный индекс для этого поля. Одним из способов создания
индексов является функция "createIndexes()".

/*--------------------------------------------------------------------------------------------------------------------*/

Составной индекс - это индекс, который затрагивает больше одного поля документа. Например, если нужно отсортировать
коллекцию по имени и дате создания, то составной индекс по двум полям создаст отсортированный список ссылок на документы
в коллекции следующим образом: сначала отсортирует документы в группы по имени, а затем отсортирует по дате создания
каждую группу документов.

При создании составного индекса порядок полей имеет критическое значение - должно действовать правило ESR (Equality,
Sort, Range), то есть сначала поля на точное совпадение (Equality), потом поля на сортировку (Sort), потом поля на
диапазон (Range). Sort из ESR используется для метода "sort()", а Range, например, для методов "find()" или
"countDocuments()" с операторами сравнения "$gt", "$lt", "$gte", "$lte", "$ne", "$in", "$nin" или "$regex". Нужно также
всегда помнить, что "$regex" с "$options: 'i'" не использует индекс.

Составные индексы в MongoDB особенно помогают, когда необходимо произвести поиск в каком-то диапазоне. Например,
составной индекс "{ ip: 1, url: 1, timestamp: -1 }" будет работать так:
1. Поля "ip" и "url" (Equality) определяют искать точное совпадение. Благодаря этим полям БД сразу попадет в нужный
блок данных, отсекая 99% записей с другими IP-адресами и другими URL. То есть сначала коллекция отсортируется в группы
по IP, а затем каждая группа отсортируется в подгруппы по URL.
2. Поле "timestamp" (Range) определяет по какому диапазону должен идти поиск. "-1" означает поиск по убыванию, "1" - по
возрастанию. В данном случае поле "timestamp: -1" сделает так, чтобы подгруппы по URL были отсортированы по значению
времени в порядке от новых к старым, что будет очень удобно, если нужно найти записи, например, за последние 10 секунд.
То есть это позволит MongoDB сканировать такой индекс в прямом порядке (слева направо) и сразу натыкаться на самые
свежие записи.

В MongoDB для одиночного индекса направление не важно, так как структура индекса (B-Tree) позволяет одинаково быстро
перемещаться по нему в обе стороны: слева направо (от меньшего к большему) и справа налево (от большего к меньшему). Но
для составных индексов направление очень важно, так как составной индекс будет эффективно работать только если
направления полей индекса такие же или полностью противоположные, как и в методе сортировки. Например, для метода
"sort({ id: 1, content: -1 })" нужно создавать индекс "{ id: 1, content: -1 }" или "{ id: -1, content: 1 }", а не
"{ id: 1, content: 1 }". Нарушение этого правила при большом количестве документов может сильно замедлить работу БД.

Для составных индексов в MongoDB действует правило префиксов: если есть составной индекс, например,
"{ userId: 1, deviceId: 1 }", то MongoDB может использовать его для запросов "find({ userId })" или
"find({ userId, deviceId })", но не сможет эффективно использовать его для запроса "find({ deviceId })", то есть MongoDB
может эффективно использовать только левый префикс составного индекса .

/*--------------------------------------------------------------------------------------------------------------------*/

На одно и то же поле нельзя создать два идентичных индекса. Однако одно и то же поле может входить в состав
неограниченного количества разных составных индексов.

/*--------------------------------------------------------------------------------------------------------------------*/

Индексы полезно использовать в следующих случаях:
1. Если очень часто повторяется какая-то операция поиска, например, если очень часто приходит запрос в БД по получению
документов по полю "email". В таком случае создание индекса по полю "email" сделает так, что MongoDB не будет перебирать
каждый документ в коллекции и сравнивать поле "email", а будет сразу точечно находить нужный документ при помощи
отсортированного по полю "email" списка ссылок на документы в коллекции. Это касается не только операций чтения,
например, "find()" или "findOne()", но и операций записи, например, "updateOne()", "deleteOne()" или "deleteMany()", так
как перед изменением или удалением документа MongoDB сначала должна его найти.
2. Если используются составные операции чтения, например, сортировка документов или получение документов из какого-то
диапазона в БД. При сортировке, если нет индексов, то MongoDB будет нужно каждый раз выгружать в RAM все подходящие
документы и сортировать их.

/*--------------------------------------------------------------------------------------------------------------------*/

Индексы вредно использовать в следующих случаях:
1. Если коллекция небольшого размера, например, не больше 50 документов. В таком случае простой перебор документов
отработает быстрее, чем работа с деревом индексов.
2. Если какая-то операция чтения редко используется. Например, если раз в неделю собирается какой-то большой отчет, то
будет целесообразнее сэкономить ресурсы на записи и не создавать индекс.
3. Если коллекция только принимает вставки документов, но поиск по ней не производится. В таком случае каждый индекс
будет замедлять вставку, не принося пользы.

В NestJS индексы для MongoDB можно создавать при помощи вызова метода "index()" у схемы, передавая в него объект с
полями для индекса, например: "BlogSchema.index({ deletedAt: 1, createdAt: -1 })".
