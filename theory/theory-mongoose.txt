Метод "lean()" в Mongoose возвращает "обычные" JavaScript объекты. Этот метод можно уточнять.

При создании схем для MongoDB не нужно указывать свойство "_id".

В Mongoose связь между моделью и коллекцией устанавливается автоматически при создании модели: берется имя модели,
преобразуется во множественное число и приводится к нижнему регистру. Или же можно просто указать имя коллекции третьим
параметром при создании модели.

Модели являются классами и предоставляют как статические методы, так и методы экземпляров для работы с БД или для
вспомогательного функционала.

Метод экземпляров модели "save()" сохраняет документ, сам определяя является ли документ новый или уже существующим.

Подход, когда сущность умеет сама себя сохранять в БД называется Active Record (AR). AR - это шаблон проектирования, в
котором объекты, содержащие данные бизнес-логики, также несут ответственность за сохранение себя в БД, а также за их
извлечение, обновление и удаление.

Метод "lean()" в Mongoose возвращает "обычные" JS-объекты.

В схемах опция "unique: true" создает уникальный индекс в БД, который гарантирует, что в коллекции не может быть двух и
более документов с одинаковым значением указанного поля, так как при вставке (атомарная операция) каждого документа
MongoDB проверяет уникальный индекс, и это происходит строго последовательно. Это помогает при race conditions.

В схемах опции "unique: true" и "index: true" запускают функцию "createIndexes()" для создания индексов.

В схемах можно отдельно создавать составные индексы.

Метод "syncIndexes()" создает и обновляет индексы в БД на основе метаданных об индексах, указанных в схемах.
Этот метод нужно использовать осторожно, так как:
1. Он удаляет индексы, созданные вне схем.
2. Также в случае очень больших коллекций этот метод при создании отсутствующего составного индекса будет перебирать всю
коллекцию для его построения, что может привести к блокировке записи и высокой нагрузке CPU/диск. В реальном приложении
лучше не использовать автоматическое создание индексов, а создавать их контролируемо, например, при помощи
скриптов-миграций, которые запускают создание, изменение и удаление индексов в периоды минимальной пользовательской
активности.

В Mongoose виртуальное свойство - это поле, которое не сохраняется в БД, но доступно у объекта в коде так, будто оно там
есть. Например (внутри класса сущности):

get id() {
  return (this as unknown as UserDocument)._id.toString();
}

В этом примере:
1. Поскольку TS не знает, что Mongoose подмешивает внутри класса "User" свойство "_id", то подсказываем TS, что у this
есть свойство "_id" при помощи "this as unknown as UserDocument".
2. В БД лежит поле "_id" типа ObjectId.
3. В коде используем свойство "user.id" и получаешь удобную строку.

Mongoose понимает геттеры из класса благодаря методу "loadClass()" схемы и автоматически регистрирует их как
виртуальные. В данном примере это позволяет работать с ID, не захламляя саму БД дубликатами данных.

При создании схемы, используя декоратор "@Schema()" из модуля @nestjs/mongoose, можно использовать флаг
"{ _id: false }", который будет говорить Mongoose не создавать автоматически поле "_id" для этой схемы.

Mongoose позволяет создавать транзакции, но в отличие от SQL, это крайняя мера. MongoDB поощряет атомарность на уровне
одного документа путем вложения в него денормализованных данных, когда, например, в PostgreSQL денормализацию данных
стоит использовать осторожно, когда есть конкретная причина для этого.
